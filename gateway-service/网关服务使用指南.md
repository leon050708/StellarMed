# Gateway 网关服务使用指南

## 🎯 Gateway 服务的作用

**Gateway 服务是整个系统的统一入口**，类似于一个"前台接待"，所有外部请求都通过 Gateway 进入系统，然后 Gateway 根据路由规则将请求转发到相应的后端服务。

### 主要功能

1. **统一入口**: 所有服务请求都通过 `http://localhost:8080` 访问
2. **服务路由**: 根据路径自动转发到对应的后端服务
3. **负载均衡**: 自动从 Nacos 发现服务并进行负载均衡
4. **跨域支持**: 配置了全局 CORS，支持前端跨域访问
5. **服务发现**: 自动从 Nacos 发现服务，无需硬编码服务地址

## 📋 服务信息

- **服务名**: `gateway-service`
- **端口**: `8888`（原 8080 被 Nacos 占用，已改为 8888）
- **访问地址**: `http://localhost:8888`

## 🔀 路由规则

Gateway 配置了以下路由规则：

### 1. 患者服务 (patient-service)
- **路径**: `/api/patients/**`, `/api/sessions/**`, `/api/chat/**`, `/api/symptoms/**`, `/api/assist/**`
- **目标服务**: `patient-service` (8101)
- **示例**:
  ```bash
  # 通过 Gateway 访问
  http://localhost:8888/api/patients
  
  # 等同于直接访问
  http://localhost:8101/api/patients
  ```

### 2. 医生确认服务 (doctor-confirm-service)
- **路径**: `/api/doctor-confirm/**`
- **目标服务**: `doctor-confirm-service` (8301)
- **示例**:
  ```bash
  http://localhost:8888/api/doctor-confirm/ai-report?patientId=1&sessionId=1001
  ```

### 3. 症状 AI 服务 (symptom-ai-service)
- **路径**: `/api/ai/symptoms/**`
- **目标服务**: `symptom-ai-service` (8201)
- **示例**:
  ```bash
  http://localhost:8888/api/ai/symptoms/extract
  ```

### 4. 检查建议 AI 服务 (test-suggestion-ai-service)
- **路径**: `/api/ai/test-suggestions/**`
- **目标服务**: `test-suggestion-ai-service` (8083)
- **示例**:
  ```bash
  http://localhost:8888/api/ai/test-suggestions/suggest
  ```

### 5. 诊断 AI 服务 (diagnosis-ai-service)
- **路径**: `/api/ai/diagnosis/**`, `/api/ai/risk/**`
- **目标服务**: `diagnosis-ai-service` (8205)
- **示例**:
  ```bash
  http://localhost:8888/api/ai/diagnosis/evaluate
  http://localhost:8888/api/ai/risk/evaluate
  ```

### 6. 总结 AI 服务 (summary-ai-service)
- **路径**: `/api/ai/session-summary/**`
- **目标服务**: `summary-ai-service` (8204)
- **示例**:
  ```bash
  http://localhost:8888/api/ai/session-summary/generate?patientId=1&sessionId=1001
  ```

### 7. 处方 AI 服务 (prescription-ai-service)
- **路径**: `/api/ai/prescriptions/**`
- **目标服务**: `prescription-ai-service` (8085)
- **示例**:
  ```bash
  http://localhost:8888/api/ai/prescriptions/generate
  ```

## 🚀 使用示例

### 方式 1: 通过 Gateway 访问（推荐）

所有请求都通过 Gateway 统一入口：

```bash
# 1. 创建患者
curl -X POST "http://localhost:8888/api/patients" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张三",
    "gender": "男",
    "age": 35
  }'

# 2. 创建会话
curl -X POST "http://localhost:8888/api/sessions?patientId=1"

# 3. AI 对话
curl -X POST "http://localhost:8888/api/chat?sessionId=1&patientId=1&question=我最近有点头痛"

# 4. 触发完整 AI 助诊流程
curl -X POST "http://localhost:8888/api/assist/full" \
  -H "Content-Type: application/json" \
  -d '{
    "patientId": 1,
    "sessionId": 1
  }'

# 5. 获取医生确认报告
curl -X GET "http://localhost:8888/api/doctor-confirm/ai-report?patientId=1&sessionId=1001"
```

### 方式 2: 直接访问服务（不推荐）

虽然可以直接访问各个服务，但不推荐：

```bash
# 直接访问 patient-service
curl http://localhost:8101/api/patients

# 直接访问 symptom-ai-service
curl http://localhost:8201/api/ai/symptoms/extract
```

## 💡 Gateway 的优势

### 1. 统一管理
- 所有服务通过一个入口访问
- 前端只需要知道 Gateway 的地址（8080）
- 后端服务端口变更不影响前端

### 2. 服务发现
- Gateway 自动从 Nacos 发现服务
- 支持服务动态注册和注销
- 自动负载均衡

### 3. 跨域支持
- Gateway 配置了全局 CORS
- 前端可以直接调用，无需配置代理

### 4. 路由灵活
- 可以根据路径、参数等条件路由
- 支持路径重写
- 支持多个服务共享同一路径前缀

## 🔍 路由工作原理

```
客户端请求
    ↓
http://localhost:8888/api/patients
    ↓
Gateway 接收请求
    ↓
匹配路由规则: /api/patients/** → patient-service
    ↓
从 Nacos 获取 patient-service 的服务实例
    ↓
负载均衡选择实例 (例如: 172.22.91.239:8101)
    ↓
转发请求到 http://172.22.91.239:8101/api/patients
    ↓
返回响应给客户端
```

## 📝 完整使用流程示例

```bash

curl -X POST "http://localhost:8080/api/chat?sessionId=1007&patientId=3&question=我最近有点头痛"

# 4. 触发完整 AI 助诊流程（通过 Gateway）
curl -X POST "http://localhost:8080/api/assist/full" \
  -H "Content-Type: application/json" \
  -d '{
    "patientId": 3,
    "sessionId": 1007
  }'

# 这个接口会自动调用：
# - symptom-ai-service: 症状结构化
# - diagnosis-ai-service: 初步诊断和风险评估
# - test-suggestion-ai-service: 检查建议
# - summary-ai-service: 问诊总结
# - prescription-ai-service: 处方建议

# 5. 医生查看报告（通过 Gateway）
curl -X GET "http://localhost:8888/api/doctor-confirm/ai-report?patientId=3&sessionId=1007"
```

## ⚙️ Gateway 配置说明

### 服务发现配置

```yaml
spring:
  cloud:
    gateway:
      discovery:
        locator:
          enabled: true  # 启用服务发现定位器
          lower-case-service-id: true  # 服务名转小写
```

这意味着 Gateway 可以自动发现 Nacos 中注册的所有服务，并使用 `lb://service-name` 进行负载均衡。

### 路由配置

```yaml
routes:
  - id: patient-service
    uri: lb://patient-service  # lb:// 表示负载均衡
    predicates:
      - Path=/api/patients/**, /api/sessions/**, ...
```

- `lb://` 前缀表示使用负载均衡
- `predicates` 定义路由匹配条件
- `Path` 匹配请求路径

## ⚠️ 注意事项

1. **Gateway 必须运行**: 所有通过 Gateway 的请求都需要 Gateway 服务运行
2. **服务必须注册到 Nacos**: Gateway 通过 Nacos 发现服务，服务必须已注册
3. **路径匹配**: 请求路径必须匹配配置的路由规则
4. **CORS 配置**: Gateway 已配置全局 CORS，前端可以直接调用

## 🔄 与直接访问服务的对比

| 特性 | 通过 Gateway | 直接访问服务 |
|------|-------------|-------------|
| 统一入口 | ✅ 是 | ❌ 否 |
| 服务发现 | ✅ 自动 | ❌ 需要知道端口 |
| 负载均衡 | ✅ 自动 | ❌ 需要自己实现 |
| CORS 支持 | ✅ 已配置 | ❌ 需要每个服务配置 |
| 路径管理 | ✅ 集中管理 | ❌ 分散在各服务 |
| 推荐使用 | ✅ 是 | ❌ 否 |

## 📚 总结

**Gateway 服务是整个系统的"门面"**，提供了：
- 🚪 统一入口（端口 8080）
- 🔀 智能路由（自动转发到对应服务）
- ⚖️ 负载均衡（自动分配请求）
- 🌐 跨域支持（前端友好）
- 🔍 服务发现（自动发现 Nacos 中的服务）

**推荐所有请求都通过 Gateway 访问**，这样前端只需要知道一个地址（8888），后端服务的变化对前端透明。

## ⚠️ 重要提示

**Gateway 端口已从 8080 改为 8888**，因为端口 8080 被 Nacos 服务器占用。如果您的 Nacos 配置了不同的端口，可以将 Gateway 改回 8080。

修改方法：编辑 `gateway-service/src/main/resources/application.yml`，将 `server.port` 改为您需要的端口。
